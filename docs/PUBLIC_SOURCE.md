# Public source boundaries

**Review before release.** A working source directory is not automatically safe to
publish. `.gitignore` protects untracked files, not files already committed to history.
Use the source-preview tool and inspect staged content before every publication.

## What belongs in source

- Application/shared Python modules, desktop adapters and supported entry points.
- Tests using synthetic/privacy-reviewed fixtures.
- Architecture, contributor and feature documentation.
- Existing GPL license, third-party notices and pinned source/build metadata.
- `data/default_openings/curation.json` and the exact pinned upstream opening inputs.
- The two explicitly approved CC0 project icon assets and their provenance/license files.
- Exactly four default runtime assets: `assets/openings/ChessWizard Default Openings.cwbook`,
  `ChessWizard Default Openings.bin`, `COPYING.txt`, `manifest.json`.

Those default assets are reproducible CC0-derived reference content. Every other editable
`.cwbook`, including the managed copy seeded into a user's profile, is private runtime
data. There is no broad exception for all opening libraries or binary files.

## Local/generated material kept out of Git

Environments and bytecode; build/dist/installer output; engine binaries/source archives;
SQLite databases and journals; profile settings; caches; managed catalogs/libraries;
backups; personal themes; screenshots; audit reports/receipts; private review sets;
local lineage manifests; credentials/environment files and editor-local state.

Nothing is deleted by the readiness audit. `.gitattributes` preserves exact source bytes
across Windows checkouts, including pinned upstream inputs whose hashes would otherwise
change under automatic newline conversion. It does not regenerate or relicense assets.

## Deliberate review holds

Fourteen historical files in `tests/fixtures/` are explicitly withheld in `.gitignore`.
They contain owner-derived source identities, game records, recorded evidence or
identity baselines. The fixtures remain available locally and unchanged. Their names
are listed in the ignore file; synthetic candidate-line/theme/SEE/skewer/X-ray fixtures
remain visible. This is a deliberate privacy hold, not accidental broad fixture exclusion.

The public suite is self-contained. Synthetic contracts live under `tests/`, and
reusable comparison/replay helpers live under `tests/support/`. Tests of exact private
historical evidence remain intact in ignored `tests/local_history/`, with the withheld
fixtures and local reports. Local discovery runs those historical tests in addition to
the public tests. They are not replaced with skip-on-missing guards. A public copy
contains neither those modules nor their data; its complete suite runs independently.

The packaging tools share `tools/package_privacy.py`. Generic rules reject runtime
DBs/sidecars, settings, cache/report/log/backup directories, managed libraries, escaping
paths, credentials and personal home paths. Only the exact shipped default opening
book is exempt from the library rule. An optional ignored `*.privacy.json` file can add
private identity strings for a particular maintainer or distribution. Its contents
must never be committed; findings expose categories, not matched values. Both the
frozen inventory and corresponding-source assembler accept `--privacy-config`.
Use that option for local distributions whose extra private identifiers are known.
The previous maintainer-specific deny rules are retained locally in ignored build
configuration rather than embedded in public Python source. This cleanup does not
certify or rebuild an existing binary.

The owner-provided ChessWizard icon was generated by the owner using ChatGPT;
the ICO is a format conversion. On 2026-09-27 the owner selected **CC0-1.0** for
these two assets. Their [provenance, hashes and permission](../packaging/windows/assets/README.md)
are documented beside them. Exact `.gitignore` exceptions now include the PNG/ICO
in the public-source preview; other images remain excluded. This resolves the
icon provenance/permission hold. Code remains GPL-3.0-or-later. Future installer
builds still require their own current package audit and release approval.

Older standalone analyzers, migration/inspection and cleanup scripts remain source
compatibility/history. Do not execute them during setup, documentation generation or
source audits. Reusable adapters may still import their calculation functions, so they
cannot all be removed simply by filename prefix.

## Preview and review

```powershell
.\.venv\Scripts\python.exe -B -m tools.public_source
```

The tool uses an isolated temporary Git repository to apply the actual root ignore
rules. It writes a hashed candidate manifest and redacted finding locations under
`build/`; it never initializes this checkout, stages, commits or contacts a remote.
A nonzero exit means review holds remain. A zero exit only means those pattern checks
passed; it is not human approval. Scan results classify examples, public references,
paths, potential secrets and owner decisions without printing matched secrets.

Before the first push, regenerate the preview, rerun clean-copy
validation and review every staged path. See [FIRST_PUBLIC_RELEASE_CHECKLIST.md](FIRST_PUBLIC_RELEASE_CHECKLIST.md).
The detailed local audit lives in ignored `reports/PUBLIC_REPOSITORY_READINESS_V1.md`.

## Reproduce the public boundary

```powershell
.\.venv\Scripts\python.exe -B tools\check_public_copy.py
```

This copies exactly the current manifest into temporary storage, checks collection,
and runs the entire copied test suite. It uses the selected interpreter's installed
dependencies; it is a source-isolation rehearsal, not a fresh dependency installation.
Private reports, historical tests, owner fixtures, user profiles and engine binaries
are absent. Logs/receipts stay under ignored `build/public-copy-check/`. The test runner
uses a temporary profile, offscreen Tk fixtures and an engine-launch guard. The public
suite still needs the supported Windows/Tk environment for desktop tests.
